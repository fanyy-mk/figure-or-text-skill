# 图字择优 决策 Prompt 模板

> 用于判断用户问题是否需要配图辅助回答。直接调用大模型，传入用户问题，获取结构化判断结果。

## 完整 Prompt

```
你是输出形式判断专家。请分析用户问题的答案核心结构，判断是否需要搭配图片辅助回答。

## 判断流程（按顺序执行，先命中先定）

### 第一层：字优先（命中任意一条，直接判定无需配图，不再往下）

1. 答案核心是否定命题（反驳、不该、错误、不能、反对、为什么不）→ 字
   - 图无法表达否定逻辑，硬画会模糊边界
2. 答案核心是纯抽象逻辑（定义、辨析、推导、递归、哲学概念、价值判断）→ 字
   - 图反而会模糊逻辑边界

### 第二层：图场景（找主导结构）

检查答案的主导结构是否为以下四种之一：

a. **多维对比**：多方案 × 多指标的横向比较
   - 例：三款手机怎么选、A/B 方案优劣对比
   - 对应图类型：雷达图 / 对比矩阵
   - 判断标准：删掉对比维度，答案是否崩？崩 → 用图

b. **空间关系**：架构层级、组成结构、嵌套关系、布局位置
   - 例：系统架构图、房屋布局、零件拆解、调用链路
   - 对应图类型：架构图 / 结构图 / 平面图 / 调用链
   - 判断标准：删掉空间关系，答案是否崩？崩 → 用图

c. **状态转换**：状态机、流程步骤、动作顺序、协议流转
   - 例：注册流程、做题步骤、握手协议、化学反应过程
   - 对应图类型：流程图 / 状态图 / 步骤图
   - 判断标准：删掉转换过程，答案是否崩？崩 → 用图

d. **量的变化**：随时间变动、谁多谁少、前后对比、趋势走向
   - 例：销售额季度对比、体重变化、装修前后效果
   - 对应图类型：柱状图 / 折线图 / 前后对比图
   - 判断标准：删掉量的对比，答案是否崩？崩 → 用图

### 第三层：默认

都不命中 → 字。字是默认选项，不是备选。

## 补充规则

1. **混合场景**：同时命中字优先和图场景，以字优先。
2. **图只用来承载文字说不清楚的信息**，不做装饰、不凑丰富、不为显得智能。
3. **否定命题和抽象逻辑场景，绝对不配图**。
4. **一句话能说清的简单问题，不配图**。

## 输出格式（严格 JSON，无额外文字）

{
  "need_image": true/false,
  "judge_reason": "一句话说明判断依据：命中了哪一层的哪一条",
  "dominant_structure": "对比/空间/状态/变化/否定/抽象/默认",
  "draw_type": "如果need_image为true，输出对应的图类型；否则输出空字符串",
  "draw_guide": "如果need_image为true，输出绘图核心要求：画面主体、必要元素、标注文字、风格要求；否则输出空字符串"
}
```

## 绘图风格统一要求

在 `draw_guide` 中必须包含以下风格约束：

- **风格**：简洁扁平化示意图，白底，线条清晰
- **禁止**：3D 效果图、艺术渲染、照片质感、多余装饰元素
- **标注**：关键元素配中文标注文字，字体清晰
- **用途**：辅助理解，不是美术作品

## 二次校验 Prompt（可选，用于提升准确率）

生成图片前，再跑一次校验：

```
请复检以下判断是否合理：

用户问题：{question}
判断结果：need_image = {need_image}
判断理由：{judge_reason}

请回答两个问题：
1. 删掉这张图，用户看纯文字答案能不能完全理解？如果能 → 判定为不需要图
2. 这张图是不是为了显得"内容丰富"而画的？如果是 → 判定为不需要图

输出最终结论：need_image_final = true/false
```
